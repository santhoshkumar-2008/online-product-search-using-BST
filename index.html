Algorithm Information

What is a Binary Search Tree?

A tree where each node has at most two children. Left subtree holds smaller keys, right subtree holds larger keys. Here the key is the Product ID.

Insertion

Start at the root, go left if the new ID is smaller, right if larger, and attach the new node at the first empty position. Duplicates are rejected.

Searching

Compare with the current node: equal means found, smaller means go left, larger means go right. Each step discards one subtree. Searching by name must visit every node because the tree is ordered by ID, not name.

Deletion

Leaf: remove it. One child: replace the node with its child. Two children: copy the inorder successor (smallest node of the right subtree) into the node, then delete the successor.

Inorder Traversal

Left → Node → Right. For a BST this visits products in sorted Product ID order.

Time Complexity

AverageWorst case
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)

Why O(n)? If IDs are inserted in sorted order (101, 102, 103...), every node goes to the right and the tree becomes a linked list of height n. Each operation then walks through all nodes. Balanced trees (AVL, Red-Black) fix this. Try it: add IDs 161, 162, 163, 164 and watch the height grow.
